# Chronicle append compatibility and EntityRelation admission

The downstream CellScaffold run [34452996847](https://github.com/Digipomps/CellScaffold/actions/runs/34452996847), on the integrated CellProtocol revision `ced03d403704f206dcdf83567989959812e49164`, exposed a compatibility regression: the relation-event guard classified every `chronicle[+]` as a protected relation event. Ordinary registration, conference preferences, and owner-local history batches therefore failed. The final consumer gate must remain required.

The correction preserves the existing append wire format. Exact `chronicle[+]` accepts an ordinary object, including legacy objects without an ID. An ID, when supplied, must be a string outside the reserved `relation-event-` namespace. A payload declaring a `haven.relation-interaction-event.*` schema must still use the validated relation-event path. Appends are excluded from relation-event collision tracking so two ordinary appends in one batch retain their original order.

Exact ordinary `chronicle[id=...]` writes validate the supplied value as well as the selector. A supplied ID must match the selector and must not enter the reserved namespace. This also closes a value-smuggling path: the generic keypath setter preserves a supplied object's ID, so checking only an innocent-looking selector was insufficient. Null remains permitted only for an exact ordinary selector; root replacement, index writes, alternate selectors, descendants, reserved IDs and schema-bypassing relation events remain denied.

Apple and Vapor call the same value-aware admission function. The older keypath-only helper remains conservative when it cannot inspect the value. Owner proof, grant enforcement, the existing interaction policy, immutable event collision checks, encryption, and journal commit rules are unchanged. No stored data is rewritten or migrated by this correction.

Regression coverage includes the original ordinary registration shape, ID-less contact history, two ordered appends alongside a protected event, selector/value mismatch, forged reserved IDs, legacy and v2 event schema smuggling, rejected-batch atomicity, and Apple/Vapor reload. Syntax and diff checks run locally; full runtime tests run in the existing macOS/Linux CI because the local disk has insufficient safe build capacity. Passing results and final consumer pins must be recorded after execution, not inferred from previous green runs.
