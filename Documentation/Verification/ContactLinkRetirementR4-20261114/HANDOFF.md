## Concrete owner boundary

The existing IdentityLinkRegistry actor owns derived, process-local revisions
and exact original ContactOperationLease registrations. Every register/restore/
revoke/clear mutation retires affected originals synchronously with linkChanged
before publishing the replacement record state. Register is per link; restore
and clear cover the whole owner; revoke is per existing link. Revisions rotate
even for identical writes: an A-to-B-to-A sequence cannot revive an old capture.
Record storage, genesis classification and sameEntityLink authorization remain
unchanged. No serialized state, original data, enrollment links or migration is
rewritten by creating these derived runtime attachments.

API for CS PersonEntityLinkEvidenceStore / authenticated admission owner:

- contactOperationRevision(ownerUUID:matching:) requires the entire original
  active IdentityLinkRecord, including linked key, scopes and binding. It returns
  an opaque non-Codable IdentityLinkContactRevision specific to this registry
  instance and write incarnation. CS evidence already retains the full record.
- attachContactOperation(_:to:) conditionally registers the exact original lease
  under that revision. Stale/foreign revisions retire the supplied lease and
  return nil. A current revision cannot revive an already retired lease. Repeated
  attachment of the same live instance to the same link returns the same handle.
- detachContactOperation(_:attachment:) matches registry, incarnation, exact
  lease object and unique handle. It retires the original with terminal BEFORE
  removal. Wrong/stale handles never detach or retire successors or siblings.

Legitimate cold recovery may call restore and rotate the registry incarnation.
Capture the FIRST revision only AFTER that recovery and after the CS owner has
revalidated the ORIGINAL evidence/link/key/home/install/request binding across
the recovery await. The registry cannot itself check those external owners.
Then retain this original revision and lease through every later await. Never fetch a fresh revision to rescue a stale authenticated
result. This registration is retirement coverage, NOT proof of authentication,
completion verification, same-Entity authority or a recipient grant. CS must
establish the correspondence between its verified evidence, requester and owner;
the generic retirement hook intentionally cannot establish that correspondence.
The existing IdentityLinkCompletionResult has a public initializer and mutable
record; do not mistake its type or an old registry comment for cryptographic
verification. Existing trusted register/restore callers retain their validation
responsibility; this slice does not change enrollment trust boundaries.

All needed authority owners must conditionally attach the SAME operation before
holder preparation/dispatch. This is not a global transaction. On any failure,
retire the original and detach completed attachments. Terminal/cancel/failure
cleanup must detach exact registrations; strong references are held until detach
or owner mutation. Fixed limits are64 registrations per link and256 per registry
(across owners/links). Idempotent same-instance attach is checked before capacity.
A new registration at capacity returns nil and retires only the supplied lease
with terminal, outside the lease lock. It does not evict existing registrations.
Expired entries still count until exact detach or owner mutation; no polling or
background sweep. Thus forgotten cleanup causes bounded denial of new operations,
not unbounded retention. These are conservative source constants, not measured
production sizing; host terminal cleanup is required before product acceptance.
No new authority or link revisions are generated by attachment requests.
Do not treat UI cancellation alone as server retirement.

There is no observer callback, task or await in mutation-to-retirement-to-record
publication. Lock order is registry actor -> lease; the final signer is lease ->
context -> synchronous crypto and must not reenter an authority owner. A private
call already admitted under the lease lock may finish before retirement obtains
that lock; retirement does not undo an earlier effect. No send/RPC/remote delivery
claim follows from this local owner hook.

## Authored regression coverage

Eleven additive methods in ContactOperationHolderTests (31 total; prior20 byte
identical outside the marked R4 block). Existing registry/genesis/binding tests,
packages and holder API retain exact parent bytes.

1. Actual signer await held while real register key replacement (same UUID/new
   key), scope replacement, identical register, identical restore, revoke and
   clear run. Observe published registry state and retired lease BEFORE release;
   then require staleIntent, zero private calls and no dispatch. Fresh restored
   authority plus a NEW operation signs; the original stays retired.
2. Complete-record mismatch (key with same UUID/scope/status), wrong owner,
   inactive stored record and foreign registry revision rejection; fresh control.
3. Capture-A/restore-B/restore-A rejects old revision although bytes match again;
   fresh capture/new operation signs.
4. Idempotent original attachment; wrong-instance handle refusal; exact terminal
   detach; same-owner sibling survives detach; stale handle cannot affect a new
   successor after restore; positive actual signer calls.
5. Fresh revision cannot reattach/revive the retired original; fresh lease works.
6. Revoke one link preserves another link and another owner; owner clear retires
   its remaining link while other owner still signs.
7. Actual two-registry conditional admission fails on stale second capture,
   retires the shared original, and exact cleanup removes first registration only
   once; a fresh shared operation succeeds and either owner can retire it.

8. Fill the per-link limit; idempotent original attach still works, overflow
   retires only the newcomer, existing operations sign, exact detach opens one
   slot, and clear retires/removes all before a new restore can attach.
9. Fill the global limit across links; a spare link cannot bypass it. Wrong
   detach frees no capacity; exact detach opens one slot; existing leases stay
   current until clear, and a newly admitted operation signs.
10. Fill a link with controlled-clock leases and expire them. Repeated fresh
    attempts fail closed at the same bound. Exact owner cleanup detaches expired
    instances and allows a new valid operation to sign.

11. Actual cold restore permits the first capture of matching original record;
    later scope replacement rejects the stale full evidence record, retires the
    original operation, and a current revision cannot rescue that operation.
    This covers CP restore, not CS evidence/key/home/install/request validation.

Fixtures use synthetic trusted restore/register inputs, not the enrollment
ceremony. Negative signer tests count the private closure; no lease.retire call
in the new block supplies the registry mutation denial. Positive signer-entry
expectations are bounded; tasks are released and joined. A later executor still
requires an external deadline and must discover all31 methods. Source controls
are text/hash/diff checks, NOT Swift compilation, discovery or behavioral tests.
